# Generated engine artifacts

The WebAssembly JavaScript, binary and declarations in `wasm/` are built from [orbyn-engine](https://github.com/orbyn-dev/orbyn-engine) base `f61b16de7ffa23bce98aae57a6781b6e732f925b` plus the exact reviewed source patch at `web/engine-patches/local-zone-purge.patch`. The patch is a local producer adaptation, not a published upstream engine revision. It adds the complete local-zone purge API used by Notes erase, preserving account/device trust and unrelated zones. No remote delete is performed. The engine source and adaptation are MIT OR Apache-2.0; both engine notices remain in `wasm/`.

`contracts/` retains the engine's generated TypeScript wire bindings from the base revision, under the same licence. This API adds no wire types. No Planner application code is included. The previous WASM artifacts were obtained from orbyn-planner at `c2d57f8ce673f3f9fcfcfb60ce3dde9aae1d0d16`; the current WASM files are rebuilt from the producer source and patch above.

`web/engine-pin.json` records the base commit, patch path/hash/file allowlist, exact Rust and wasm-bindgen versions, and all four artifact hashes. The pin does not claim the patch is contained in the base commit. Run `node web/scripts/verify-engine.mjs` from the repository root before builds. It checks the patch and complete runtime artifact set together. No runtime download or alternate crypto implementation is used.

To reproduce, use an isolated engine checkout at the exact base revision. Verify the patch SHA256 against the pin, then use `git apply --check` and `git apply` with this patch. Install the recorded Rust WASM target and exact wasm-bindgen build CLI in an explicitly chosen build environment. From `web/`, run `node scripts/build-engine.mjs <engine-checkout>`. It requires the exact base plus exact patch, its file allowlist and no untracked build inputs; it refuses other tracked source changes. It verifies the recorded compiler/CLI versions, passes the checked compiler explicitly as Cargo’s RUSTC, and refuses compiler wrappers. `ORBYN_CARGO`, `ORBYN_RUSTC` and `ORBYN_WASM_BINDGEN` may select explicit executable paths without changing global PATH; `CARGO_TARGET_DIR` can keep rebuildable output outside the checkout.

The build defines its own encoded Rust flags: source locations under the engine checkout, Cargo home and Rustup home are remapped to stable `/orbyn-build/` prefixes. This prevents personal build paths from entering distributed WASM diagnostics, including Windows paths and roots with spaces. Caller-supplied Rust flag environment variables are rejected. These controlled flags take precedence over Cargo configuration `rustflags`; configure other build requirements explicitly rather than relying on additional Rust flags.

Review generated differences and update hashes deliberately. Cross-toolchain byte identity is not assumed. The producer's existing release strip setting causes a wasm-bindgen target-features warning; this build does not change that producer setting. Source compatibility, real-WASM erase/reload/failure/account-isolation tests and the source patch review remain required qualification; hash verification alone does not prove behavior.
